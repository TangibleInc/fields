# Dynamic Values

Dynamic values are placeholders stored in the field value, and resolved from PHP
when the value is rendered.

## Activate on a field

To add support for dynamic values on a field, add `dynamic` to the field
definition.

<CodeTabs>

```php
$fields->render_field('text-with-dynamic-values', [
  'type'    => 'text',
  'label'   => 'Text field',
  'value'   => $fields->fetch_value('text-with-dynamic-values'),
  'dynamic' => true
]);
```

```jsx
const { Field } = window.tangibleFields

<Field
  type="text"
  name="text-with-dynamic-values"
  label="Text field"
  dynamic={true}
/>
```

</CodeTabs>

<Canvas of={DynamicStories.TextInsert} />

Instead of `true`, an array configures the picker:

- `mode`: `insert` or `replace`
- `types`: the value types offered, from `text`, `date`, `color` and `number`
- `categories`: the categories offered, all of them if not defined

## Modes

- `insert`: mix regular text and several dynamic values in the same value
- `replace`: replace the whole field value with a single dynamic value

```php
$fields->render_field('text-with-dynamic-values', [
  // ...
  'dynamic' => [
    'mode' => 'replace'
  ]
]);
```

<Canvas of={DynamicStories.TextReplace} />

## Field types

| Field type | Modes | Value types |
| --- | --- | --- |
| `text` | `insert` (default), `replace` | text, date, color, number |
| `number` | `replace` | number |
| `color-picker` | `replace` | color |
| `date-picker` | `replace` | date |

## Built-in values

| Value | Category | Settings |
| --- | --- | --- |
| `post_id` | Post | |
| `post_meta` | Post | `source`, `post_id`, `meta_name` |
| `user_id` | User | |
| `user_meta` | User | `source`, `meta_name` |
| `date` | General | `date_type`, `custom_date_picker`, `delay`, `delay_number`, `delay_type`, plus the [date helper](#date-helper) settings |

`post_meta` and `user_meta` can be stored by administrators only.

## Register a category

Each category is a group of dynamic values.

```php
$fields->register_dynamic_value_category('post', [
  'label' => 'Post',
]);
```

## Register a value

```php
$fields->register_dynamic_value([
  'category'    => 'post',
  'name'        => 'post_id',
  'label'       => 'Post ID',
  'type'        => 'text',
  'description' => 'Return the current post ID, if any',
  'callback'    => function($settings, $config) {
    return $config['context']['current_post_id'];
  },
  'permission_callback' => '__return_true'
]);
```

- category (required): Slug of the associated category
- name (required): Slug of the dynamic value
- label: If not defined, name will be used
- description: Used both in the documentation and in the setting form
- type: The type of data returned by the callback, either `color`, `date`,
  `number` or `text`
- callback: Function used to render the dynamic value. It receives the
  settings set by the user, and the config described in the
  [Context](#context) section
- permission_callback: Evaluates if the current user can store and parse the
  value
- fields: Settings of the dynamic value

The category has to be registered first. The built-in categories are
registered on `init`, so values added to them use a later priority:

```php
add_action('init', function() use($fields) {
  $fields->register_dynamic_value([
    'category' => 'post',
    // ...
  ]);
}, 20);
```

### Settings

Settings are defined with an array of fields, using the same syntax as regular
fields (any field type can be used, and visibility conditions are supported).
The user sets them when inserting the value, and they are passed to the callback.

```php
$fields->register_dynamic_value([
  'category' => 'post',
  'name'     => 'post_title',
  'label'    => 'Post title',
  'type'     => 'text',
  'fields'   => [
    [
      'type'    => 'select',
      'name'    => 'format',
      'label'   => 'Format',
      'choices' => [
        'none'      => 'None',
        'lowercase' => 'Lowercase',
        'uppercase' => 'Uppercase'
      ]
    ]
  ],
  'callback' => function($settings, $config) {

    $format = $settings['format'] ?? 'none';
    $post_title = get_the_title(
      $config['context']['current_post_id']
    );

    if( $format === 'lowercase' ) return strtolower($post_title);
    if( $format === 'uppercase' ) return strtoupper($post_title);

    return $post_title;
  },
  'permission_callback' => '__return_true'
]);
```

### Permissions

Two actions are evaluated, and the callback has to return `true` for the action
to be allowed:

- permission_callback_store: If the current user can save the dynamic value.
  Values the user cannot store are not offered in the picker
- permission_callback_parse: If the current user can parse the dynamic value.
  Values the user cannot parse are removed from the string before rendering

```php
$fields->register_dynamic_value([
  // ...
  'permission_callback_store' => function() {
    return in_array('administrator', wp_get_current_user()->roles ?? []);
  },
  'permission_callback_parse' => '__return_true'
]);
```

When both actions share the same callback, `permission_callback` can be used
instead:

```php
$fields->register_dynamic_value([
  // ...
  'permission_callback' => function() {
    return is_user_logged_in();
  }
]);
```

### Date helper

For values returning a date, `dynamic_values_date_helper` provides the format
and timezone settings, and a function to render a timestamp with them.

```php
$fields->register_dynamic_value([
  'category' => 'post',
  'name'     => 'post_date',
  'label'    => 'Post date',
  'type'     => 'date',
  'fields'   => [
    ...$fields->dynamic_values_date_helper['settings']
  ],
  'callback' => function($settings, $config) use($fields) {
    $timestamp = get_post_timestamp( $config['context']['current_post_id'] );
    return $fields->dynamic_values_date_helper['render']( $timestamp, $settings );
  },
  'permission_callback' => '__return_true'
]);
```

The helper settings are `date_format`, `custom_date_format` and
`date_timezone`.

## Render a value

Dynamic values are stored as
`[[dynamic_value_name::setting=value::setting2=value2]]`, and rendered with
`render_value`:

```php
$value = 'User ID: [[user_id]]';

// Outputs something like "User ID: 1"
$output = $fields->render_value($value);
```

For registered fields, it is applied after fetching the value:

```php
$output = $fields->render_value(
  $fields->fetch_value('field_name')
);
```

Unregistered values are left as-is.

### Context

The second parameter of `render_value` is a config array. Its `context` key
is merged over a default context, then passed to the callback of each dynamic
value found in the string.

The default context is:

- current_user_id: The current user ID
- current_post_id: The ID of the current post in the loop, if any

To render a value for another post or user than the current one, pass a
context:

```php
// Assuming the current user id is 1, returns "User ID: 1"
$fields->render_value('User ID: [[user_id]]');

// While this returns "User ID: 2"
$fields->render_value('User ID: [[user_id]]', [
  'context' => [
    'current_user_id' => 2
  ]
]);
```

Any key can be added to the context, and read from the callback of a
registered value:

```php
$fields->register_dynamic_value([
  'category' => 'order',
  'name'     => 'order_total',
  'label'    => 'Order total',
  'type'     => 'number',
  'callback' => function($settings, $config) {
    return get_post_meta( $config['context']['order_id'] ?? 0, 'total', true );
  },
  'permission_callback' => '__return_true'
]);

$fields->render_value('Total: [[order_total]]', [
  'context' => [
    'order_id' => $order_id
  ]
]);
```

Only the context reaches the callback.

### Action

Before rendering, values the current user cannot parse are removed from the
string. The `action` key of the config selects the permission checked, `parse`
by default. With `evaluate`, used by the
[conditional logic evaluation](?path=/docs/features-conditional-logic--docs#evaluate),
no permission is checked.

## Hooks

`tangible_fields_dynamic_value` filters each value definition at registration:

```php
add_filter('tangible_fields_dynamic_value', function(array $dynamic_value) {
  if( $dynamic_value['name'] === 'post_id' ) {
    $dynamic_value['label'] = 'Current post ID';
  }
  return $dynamic_value;
});
```

`tangible_fields_dynamic_value_general_date` filters the date of the built-in
`date` value, before delay and format are applied. It supports extra
`date_type` choices, added with the previous filter:

```php
add_filter('tangible_fields_dynamic_value_general_date', function($date, array $settings, array $config) {
  if( $settings['date_type'] === 'post_date' ) {
    return tangible\date()->fromTimestamp(
      get_post_timestamp( $config['context']['current_post_id'] )
    );
  }
  return $date;
}, 10, 3);
```

## Custom integration

To pick dynamic values from your own UI (a page builder dialog, a block editor
toolbar), the settings dialog that fields open from their dynamic value button
is exported on its own.

```jsx
const { DynamicFieldSettings, dynamicValues } = window.tangibleFields

<DynamicFieldSettings
  open={ open }
  onOpenChange={ setOpen }
  dynamic={ dynamicValues.createAPI({ categories: ['post'] }) }
  modes={ ['builtin'] }
  labels={{ title: 'Insert a field', select: 'Field' }}
  portalContainer={ host }
  context="wp"
  onSubmit={ (token, meta) => insert(token, meta.label) }
/>
```

- dynamic (required): The API returned by `dynamicValues.createAPI()`, which
  takes the same `types`, `categories` and `mode` options as the `dynamic`
  field attribute
- onSubmit (required): Receives the token, in the stored format
  `[[name::setting=value]]`, and a `meta` object describing the pick (`mode`,
  `value`, `label`, `group`, `settings`)
- modes: The modes offered, `['builtin', 'custom']` by default. A single mode
  hides the Field Type toggle
- labels: Every string of the dialog, see `dynamicValues.defaultLabels` for the
  keys
- portalContainer: Where the dialog is rendered, the same attribute fields
  accept. `document.body` by default
- context: The style context used when rendered outside any field
- editingId, editingRaw: Set both to edit an existing token instead of
  inserting a new one. `editingRaw` is the token, with or without its `[[ ]]`
