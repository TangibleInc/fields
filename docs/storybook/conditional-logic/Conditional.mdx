# Conditional Logic

Conditional logic is a way to let users define conditions with the
conditional panel field, and evaluate them from PHP.

## Conditional panel

The conditional panel is a field type. Each row is a condition, made of a left
value, an operator and a right value. Conditions in the same group are joined
with AND, and groups are joined with OR.

<CodeTabs>

```php
$fields->render_field('conditions', [
  'type'  => 'conditional_panel',
  'label' => 'Conditions',
  'value' => $fields->fetch_value('conditions'),
]);
```

```jsx
const { Field } = window.tangibleFields

<Field
  type="conditional-panel"
  name="conditions"
  label="Conditions"
/>
```

</CodeTabs>

<Canvas of={ConditionalStories.Panel} />

### Operators

By default every operator is available. The `operators` attribute restricts
the list and sets the labels:

<CodeTabs>

```php
$fields->render_field('conditions', [
  'type'      => 'conditional_panel',
  'label'     => 'Conditions',
  'operators' => [
    '_eq'       => 'Is',
    '_neq'      => 'Is not',
    '_contains' => 'Contains',
  ]
]);
```

```jsx
<Field
  type="conditional-panel"
  name="conditions"
  label="Conditions"
  operators={{
    _eq: 'Is',
    _neq: 'Is not',
    _contains: 'Contains',
  }}
/>
```

</CodeTabs>

<Canvas of={ConditionalStories.Operators} />

The operators are the same as for visibility conditions, see the
[operator list](?path=/docs/features-field-visibility--docs#operators).

### Dynamic values

The left and right values offer dynamic values in replace mode. The `dynamic`
attribute restricts them, with the same `categories` and `types` options as on
other fields.

<CodeTabs>

```php
$fields->render_field('conditions', [
  'type'    => 'conditional_panel',
  'label'   => 'Conditions',
  'dynamic' => [
    'categories' => [ 'post' ],
    'types'      => [ 'text', 'number' ]
  ]
]);
```

```jsx
<Field
  type="conditional-panel"
  name="conditions"
  label="Conditions"
  dynamic={{ categories: ['post'], types: ['text', 'number'] }}
/>
```

</CodeTabs>

<Canvas of={ConditionalStories.DynamicValues} />

More about this in the
[Dynamic Values page](?path=/docs/features-dynamic-values--docs).

### Modal

With `use_modal`, the panel opens in a modal. Changes are discarded when the
modal is closed without saving.

<CodeTabs>

```php
$fields->render_field('conditions', [
  'type'      => 'conditional_panel',
  'label'     => 'Conditions',
  'use_modal' => true,
]);
```

```jsx
<Field
  type="conditional-panel"
  name="conditions"
  label="Conditions"
  useModal={true}
/>
```

</CodeTabs>

### Custom fields

The `fields` attribute replaces the three default fields of a condition. Any
field type can be used, with the names `left_value`, `operator` and
`right_value`.

<CodeTabs>

```php
$fields->render_field('conditions', [
  'type'   => 'conditional_panel',
  'label'  => 'Conditions',
  'fields' => [
    [
      'type'    => 'select',
      'name'    => 'left_value',
      'label'   => 'Subject',
      'choices' => [
        '[[post_id]]'    => 'Post ID',
        '[[post_title]]' => 'Post title',
      ]
    ],
    [
      'type'    => 'select',
      'name'    => 'operator',
      'label'   => 'Operator',
      'choices' => [
        '_eq'  => 'Is',
        '_neq' => 'Is not',
      ]
    ],
    [
      'type'  => 'text',
      'name'  => 'right_value',
      'label' => 'Value',
    ]
  ]
]);
```

```jsx
<Field
  type="conditional-panel"
  name="conditions"
  label="Conditions"
  fields={[
    {
      type: 'select',
      name: 'left_value',
      label: 'Subject',
      choices: {
        '[[post_id]]': 'Post ID',
        '[[post_title]]': 'Post title',
      }
    },
    {
      type: 'select',
      name: 'operator',
      label: 'Operator',
      choices: {
        _eq: 'Is',
        _neq: 'Is not',
      }
    },
    {
      type: 'text',
      name: 'right_value',
      label: 'Value',
    }
  ]}
/>
```

</CodeTabs>

<Canvas of={ConditionalStories.CustomFields} />

Without `choices` on the `operator` field, new conditions start with an empty
operator.

## Stored value

The value is a JSON string: an array of groups, each group holding its
conditions in `data`. Keys are generated by the panel to identify rows.

```json
[
  {
    "key": "60be9330eb99c0",
    "data": [
      {
        "key": "60be9330ebae0c",
        "left_value": "[[post_id]]",
        "operator": "_eq",
        "right_value": "5"
      },
      {
        "key": "60be93e414b920",
        "left_value": "[[site_title]]",
        "operator": "_contains",
        "right_value": "Tangible"
      }
    ]
  },
  {
    "key": "60be9330eb99c1",
    "data": [
      {
        "key": "60be93e414b921",
        "left_value": "[[post_title]]",
        "operator": "_neq",
        "right_value": "Hello world"
      }
    ]
  }
]
```

This value reads as: (post ID is 5 AND site title contains Tangible) OR (post
title is not Hello world).

## Evaluate

To evaluate a value saved by the conditional panel, we use
`evaluate_conditional`. It takes the decoded value and returns a boolean.

```php
$conditions = json_decode( $fields->fetch_value('conditions') );

if( $fields->evaluate_conditional( $conditions ) ) {
  // ...
}
```

An empty value evaluates to `true`.

Dynamic values in the conditions are rendered before the comparison. The
second parameter is the config passed to their callbacks, the same as for
`render_value`. To evaluate conditions for another post or user than the
current one, pass a context:

```php
$fields->evaluate_conditional( $conditions, [
  'context' => [
    'current_post_id' => $post_id
  ]
]);
```

More about the context in the
[Dynamic Values page](?path=/docs/features-dynamic-values--docs#context).

The permissions of the dynamic values are not checked during evaluation.

## Evaluate a condition

Conditions can also be written by hand and evaluated with `evaluate_condition`.
The left value is the key, the operator and right value are the value:

```php
// true when the current user ID is 1
$fields->evaluate_condition([
  '[[user_id]]' => [
    '_eq' => 1
  ]
]);
```

Dynamic values are rendered on both sides before the comparison, alone or mixed
with text. The second parameter is the same config as for `evaluate_conditional`.

```php
$fields->evaluate_condition([
  'User id is [[user_id]]' => [
    '_eq' => 'User id is 1'
  ]
]);
```

### Relations

The `_and` and `_or` keys group conditions, and can be nested.

```php
$fields->evaluate_condition([
  '_or' => [
    '[[post_id]]' => [
      '_eq' => 5
    ],
    '_and' => [
      '[[user_id]]'   => [ '_eq' => 1 ],
      '[[post_type]]' => [ '_in' => [ 'post', 'page' ] ],
    ]
  ]
]);
```

Several conditions at the top level are joined with AND. The left value is an
array key, so the same left value appears once per relation.

An unknown operator evaluates to `false`, and an empty condition to `true`.
